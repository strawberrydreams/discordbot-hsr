# 변경 이력

[English changelog](CHANGELOG.md)

이 문서는 커밋 목록 대신 Hyacine이 제품으로서 어떻게 발전했는지를 기록합니다.
구현 세부사항보다는 사용자가 체감하는 동작, 호환성, 운영 영향을 중심으로 정리합니다.

아래 기간에는 저장소가 릴리스 태그를 사용하지 않았습니다. 따라서 버전 번호는 과거
이력을 기능 마일스톤 단위로 재구성한 것이며, 각 날짜는 해당 마일스톤에 포함된 마지막
변경일입니다.

## [Unreleased]

### Added (새로운 기능)

- 웹 관리에서 서버별 파티·공지·이벤트 채널과 금지어 필터 사용 여부를 저장하고,
  공지 작성 시 Discord 문법 가이드를 확인할 수 있습니다.

### Improved (기존 기능 개선)

- `/설정` 하위 명령을 `Administrator` 권한 사용자에게만 표시하고 실행하도록
  제한했습니다.
- `/게임카드` 제목에 Discord 닉네임과 게임 이름을, 본문 두 줄에 게임 계정과 첫 진열
  캐릭터 정보를 표시합니다.
- OpenAI 크레딧 소진 안내에서 별도 이미지 API 설명을 제거했습니다.
- `/설정`은 `시작`, `공지허용`, `확인`만 남기고 채널과 금지어 필터 설정을 localhost
  웹 관리로 이전했습니다. 웹 공지 수신 동의는 Guild 관리자만 Discord에서 바꿀 수
  있고, 웹 작업의 건너뜀·실패 결과에는 핵심 원인을 함께 표시합니다.
- Gemini 이미지 API의 할당량 또는 결제 한도가 소진되면 운영 조치를 안내합니다.
- SQLite·백업·export·생성 이미지 파일을 소유자 전용 권한으로 제한하고, 환경 파일과
  localhost 웹 인증 및 의존성 감사를 강화했습니다.

### Fixed (버그 수정)

- 최신 aiohttp가 보안 헤더 미들웨어를 호출할 때 웹 관리 요청이 실패하던 문제를
  수정했습니다.
- 파티 채널 저장 실패가 기존 패널 복구 정보를 지우거나 성공으로 보고하던 문제와,
  Gemini quota 거부가 사용자 일일 이미지 한도를 소비하던 문제를 수정했습니다.

## [0.7.0] - 2026-08-21 — 게임 카드와 선택형 파티 모집

### Added (새로운 기능)

- 파티 채널에 게임 선택 패널을 추가하고, 선택한 게임의 모집 패널만 생성하도록
  변경했습니다. 모든 모집 패널에 명시적인 `나가기` 버튼이 표시됩니다.
- 길드별 웹 공지 채널 설정과 공지 이미지 1개 첨부 기능을 추가했습니다.

### Improved (기존 기능 개선)

- `/프로필카드`를 `/게임카드`로 바꾸고 인게임 진열창 첫 캐릭터의 Enka 이미지를
  Discord 임베드에 직접 표시하도록 개선했습니다.
- `/상태`를 명령 사용자에게만 표시하고 일일 한도가 사용자별·봇 인스턴스 전체임을
  명시했습니다.
- 기존 기본 파티 채널 `🎮-파티`를 재시작 시 `🎮-디스코-파티`로 자동 변경합니다.

### Fixed (버그 수정)

- 금지어 응답의 10초 쿨다운을 제거했습니다.
- OpenAI 크레딧 소진을 일반 혼잡과 구분해 운영 조치를 안내하며, 별도 Gemini 이미지
  기능은 계속 사용할 수 있음을 표시합니다.

### Breaking Changes (호환성 변경)

- `/프로필카드` 명령은 `/게임카드`로 대체되었습니다.
- 길드 설정 DB는 기동 시 v5로 자동 마이그레이션됩니다. 웹 공지를 사용하려면 길드에서
  `/설정 공지채널`을 한 번 지정해야 합니다.

## [0.6.0] - 2026-08-11 — 호스트가 운영하는 커뮤니티 서비스

Hyacine은 Discord 안에서만 쓰는 봇에서, 운영자가 일상적인 변경을 위해 매번 파일을
직접 편집하지 않아도 되는 로컬 관리 서비스로 발전했습니다.

### Added (새로운 기능)

- 길드가 별도의 음악 봇 없이 Discord에서 URL 대기열을 관리할 수 있도록 선택형 음성
  재생 기능과 영속 음악 제어 패널을 추가했습니다.
- 호스트 운영자가 AI 페르소나, 금지어, 게임 목록을 편집할 수 있도록 `ADMIN_TOKEN`으로
  활성화하는 localhost 전용 웹 관리 페이지를 추가했습니다.
- 한 자가 호스팅 봇으로 여러 커뮤니티를 기본 방송 없이 운영할 수 있도록 길드 개요와
  opt-in 방식의 호스트 공지 기능을 추가했습니다.
- 각 길드가 제어 패널 위치를 정할 수 있도록 `/설정 음악채널`과 음악 패널 상태를 길드
  설정에 추가했습니다.

### Improved (기존 기능 개선)

- 음악 제어가 재시작 후에도 복원되며, 대기열 제거·건너뛰기·일시정지·정지에 요청자와
  관리자 권한을 구분해 적용하도록 개선했습니다.
- 웹에서 편집한 설정을 검증 후 원자적으로 저장하도록 개선했습니다. 금지어는 즉시 다시
  불러오며, 페르소나와 게임 변경은 문서화된 적용 시점에 반영됩니다.
- 컨테이너 배포에서도 같은 로컬 운영 흐름을 쓸 수 있도록 Docker Compose가 관리자
  페이지를 호스트 loopback에만 공개하도록 개선했습니다.

### Fixed (버그 수정)

- 미디어 해석이 느릴 때 봇 이벤트 루프와 다른 명령까지 응답하지 않던 문제를
  수정했습니다.
- 재시작 또는 채널 변경 후 음악·파티 패널의 상태가 어긋나는 문제를 보완하고 오래된
  패널 상호작용을 거부하도록 수정했습니다.
- 웹 관리가 위험한 파일시스템 구조, 잘못된 세션, cross-site 요청, 과도하게 큰 입력,
  잘못된 대상 길드를 거부하도록 수정했습니다.
- 설정 읽기 실패를 기본값으로 조용히 덮어쓰지 않고 운영자에게 표시하도록 수정했습니다.

### Breaking Changes (호환성 변경)

- 없음. 웹 인터페이스와 음악 extension은 모두 opt-in입니다. `ADMIN_TOKEN`을 비워
  두거나 `PyNaCl`/`yt-dlp`를 설치하지 않은 환경은 필수 데이터 마이그레이션 없이 기존
  봇 동작을 유지합니다.

### Internal (내부 변경)

- 새 운영 화면을 위해 명령, 웹 보안, 파일시스템, 패널 상태 회귀 테스트를
  추가했습니다.
- Compose 백업 서비스가 봇 이미지를 재사용하되 provider 자격 증명은 받지 않도록
  구성했습니다.

## [0.5.0] - 2026-08-04 — 공개 자가 호스팅과 영속 패널

원래 서버 밖의 운영자도 쓸 수 있도록 준비하면서, 소스 코드 직접 수정 방식을 검증된
설정 파일과 길드별 자체 설정 방식으로 바꿨습니다.

### Added (새로운 기능)

- 공개 설치에서 Python 모듈을 수정하지 않고 동작을 바꿀 수 있도록 example 파일이 있는
  `settings/persona.json`, `settings/forbidden_words.json`,
  `settings/games.json`을 추가했습니다.
- 길드 관리자가 Discord에서 자기 서버를 설정할 수 있도록 `/설정 시작`,
  `/설정 파티채널`, `/설정 공지허용`, `/설정 확인`을 추가했습니다.
- 매번 설정 명령을 다시 실행하지 않아도 모집 기능이 유지되도록 재시작 후 복원되는 게임
  패널을 추가했습니다.
- 포인트 비용 외에도 provider 지출을 앱 수준에서 제한할 수 있도록 기본 대화, 고급 대화,
  이미지 생성에 KST 기준 사용자별 일일 한도를 추가했습니다.
- 업그레이드와 복구 과정에서 다루는 데이터 형식을 검증할 수 있도록 SQLite 스키마 버전과
  설정 파일을 포함하는 백업을 추가했습니다.
- 명확한 운영 조건으로 프로젝트를 배포할 수 있도록 MIT 라이선스와 자가 호스팅 중심 설치
  가이드를 추가했습니다.

### Improved (기존 기능 개선)

- 핵심 실행에는 `DISCORD_TOKEN`만 필요하도록 개선했습니다. provider 키가 없으면 AI 또는
  이미지 extension만 건너뛰므로 비-AI 배포도 사용할 수 있습니다.
- 운영자가 안전하게 조정할 수 있도록 AI 모델명, cooldown, 비용 관련 한도, 데이터 경로,
  백업 정책을 런타임 설정으로 옮겼습니다.
- 봇 동작까지 재현할 수 있는 복구본을 만들기 위해 검증된 SQLite snapshot과 운영자 JSON
  설정을 함께 백업하도록 개선했습니다.
- `/이벤트`를 길드 어느 채널에서나 사용할 수 있게 하고, 항상 같은 순서의 이벤트 목록을
  표시하도록 개선했습니다.

### Fixed (버그 수정)

- 설정 파일이 없거나, 문법이 잘못되거나, UTF-8이 아니거나, 일부 항목이 유효하지 않아도
  관련 없는 extension까지 중단되지 않도록 수정했습니다. 오류를 표시하고 안전한
  fallback을 사용합니다.
- 패널 생성 전 게임 이름, 역할 목록, 정원, Discord component 크기를 검증하도록
  수정했습니다.
- 기존 DB 업그레이드 경로를 보존하고, 지원하지 않는 새 스키마는 호환되지 않는 구조로
  열지 않고 명확하게 실패하도록 수정했습니다.
- 패널 설정 중 느린 상호작용을 defer하고, 관리 응답을 비공개로 유지하며, 길드·게임별 최신
  패널 하나만 유효하도록 수정했습니다.

### Breaking Changes (호환성 변경)

- 파티 명령 API `/모집`, `/파티`, `/나가기`, `/변경`을 영속 게임 패널 버튼으로
  대체했습니다. 업그레이드 후 운영자는 `/설정`으로 파티 채널을 지정해야 합니다.
- 코드에 고정되어 있던 게임·페르소나 설정을 `settings/` 아래 세 JSON 파일로
  대체했습니다. 기존 `runtime/data/forbidden_words.json`은
  `settings/forbidden_words.json`으로 옮겨야 합니다.
- 채널 ID를 환경변수에서 `guild_settings.db`로 옮겼습니다. 이제 각 길드가 파티 채널과
  공지 수신 여부를 소유합니다.
- 파티 스키마 v2에 `host_id`를 추가하고, 한 사용자가 길드에서 하나의 활성 파티에만
  참가하도록 제한했으며, 역할 점유를 고유하게 만들었습니다. 마이그레이션 중 기존 중복
  참가는 결정적인 하나로 축소되고 방장이 지정됩니다.
- `attendance_data.db`에 사용자, KST 날짜, 명령을 key로 하는 `ai_usage` table이
  추가되었습니다. 포인트 잔액과 달리 AI 사용량은 의도적으로 여러 길드에 걸쳐
  공유됩니다.
- 길드 설정 데이터 모델이 기존 모집/이벤트 채널 필드에서 파티 채널, 음악 채널, 패널
  메시지, 공지 opt-in 필드로 변경되었습니다. 지원되는 기존 행은 자동으로
  마이그레이션됩니다.

### Internal (내부 변경)

- 런타임 loader와 이후 운영 도구가 함께 쓰는 JSON 검증 및 원자적 쓰기 계약을
  도입했습니다.
- API 키 없는 테스트, 스키마 마이그레이션 테스트, 백업 staging 검사, 공개 배포 계약
  검사를 확대했습니다.

## [0.4.0] - 2026-07-31 — 신뢰할 수 있는 멀티 길드 운영

Hyacine은 단일 서버용 개인 배포에서 복구 가능한 데이터와 명시적인 포인트 경제 규칙을
갖춘 로컬 운영 멀티 길드 봇으로 발전했습니다.

### Added (새로운 기능)

- 검증되지 않은 복사본을 신뢰하지 않고 데이터를 복구할 수 있도록 SQLite 온라인 백업,
  보존 정책, manifest, staged restore 검사를 추가했습니다.
- 시작 상태 검증, 로그, 운영 runbook을 갖춘 Docker Compose와 macOS LaunchAgent 배포
  방식을 추가했습니다.
- 모든 차감·지급·환불을 잔액과 대조할 수 있도록 append-only 포인트 원장을
  추가했습니다.
- 한 사용자나 채널이 메모리와 요청 부하를 무한히 늘리지 못하도록 사용자별 AI cooldown과
  크기가 제한된 대화 세션을 추가했습니다.
- 한 봇 인스턴스가 포인트, 금지어 횟수, 파티를 섞지 않고 여러 Discord 서버를 지원할 수
  있도록 길드별 설정과 데이터 소유 경계를 추가했습니다.

### Improved (기존 기능 개선)

- 공유 채널에서 개인 입력이 불필요하게 노출되지 않도록 관련 명령 prompt와 응답을
  ephemeral로 개선했습니다.
- 파티 상호작용을 재시작 후에도 유지하고, 멤버 퇴장 시 자리를 반환하며, 생성·정원·역할·
  참가 규칙을 데이터베이스 계층에서 강제하도록 개선했습니다.
- 느린 외부 서비스가 봇을 멈추지 않도록 금융 조회를 이벤트 루프 밖으로 옮기고 timeout과
  cache를 추가했습니다.
- 봇과 백업의 동시 접근을 더 안전하게 처리하도록 SQLite에 WAL mode, 더 긴 busy timeout,
  일관된 connection 종료를 적용했습니다.
- 수정된 메시지도 금지어 검사 대상에 포함하고, 사용자 입력이 길드 전체를 호출하지 않도록
  모든 봇 출력에서 mention 확장을 막았습니다.
- 반복 조회 결과를 더 쉽게 이해할 수 있도록 이벤트 목록 순서를 결정적으로 만들고 길드
  nickname을 우선 표시했습니다.

### Fixed (버그 수정)

- 동시 요청에서 일일 출석 보상이 중복 지급되거나 잔액이 음수가 되지 않도록 출석 처리와
  포인트 차감을 원자적으로 수정했습니다.
- 고급 대화와 이미지 요청 실패 시 한 번만 환불하고, Discord interaction defer 전에
  실패하면 사용자에게 비용을 청구하지 않도록 수정했습니다.
- 유령 파티원, 중복 역할, 잘못된 timestamp, 반환되지 않은 자리, 재시작 후 깨진 버튼을
  일관되게 정리하거나 거부하도록 수정했습니다.
- Cog를 불러오기 전에 DB를 검증하고 운영 경로나 상태가 안전하지 않으면 시작을 중단하도록
  수정했습니다.
- 운영 및 복구 중 파일이 잠기지 않도록 데이터베이스와 백업 handle을 확실히 닫도록
  수정했습니다.

### Breaking Changes (호환성 변경)

- 대화 명령 API가 `/대화`와 `/기본`·`/고급` mode 전환 방식에서 명시적인
  `/기본대화`와 `/고급대화` 명령으로 변경되었습니다.
- `/럭키박스`와 관련 DB 필드를 제거했습니다. AI 가격의 안정적인 근거를 만들기 위해
  출석만 새 포인트를 발행합니다.
- secret과 runtime 설정을 `.env.secrets`와 `.env.runtime`으로 분리했습니다. 기존
  `.env` 또는 키별 파일을 쓰던 배포는 값을 옮겨야 합니다.
- 런타임 데이터를 설정 가능한 `runtime/data`, `runtime/backups` 아래로 옮겼으며, 운영
  시작 시 안전하지 않거나 잘못된 경로 구조를 거부합니다.
- 출석 repository API는 `(guild_id, user_id)`, 파티 API는 `(guild_id, game)`을
  필수로 받도록 변경되었습니다. 해당 SQLite 기본키와 원장 행에도 `guild_id`가
  추가되었으므로 격리 이전 데이터는 사용 전에 마이그레이션해야 합니다.
- SQLite만 지원하는 backend로 확정했습니다. 이전에 문서에만 있고 구현되지 않았던
  `DB_URL` 확장 경로는 제거했습니다.

### Internal (내부 변경)

- 동시성, 포인트 정산, moderation, 배포, process lifecycle을 포괄하는 회귀 테스트를
  추가했습니다.
- 사용하지 않는 스크립트를 제거하고 비공개 런타임 파일을 Git worktree 밖으로
  격리했습니다.

## [0.3.0] - 2026-06-11 — 통합 모듈 아키텍처

새 기능이 영속 계층을 공유하고 Discord 연결 없이 테스트될 수 있도록, 코드베이스를 하나의
지원되는 Cog 기반 애플리케이션으로 정리했습니다.

### Added (새로운 기능)

- 사용자 데이터를 공유하는 명령의 영속 처리를 한곳에 모으기 위해 SQLite 구현을 갖춘
  출석·파티 repository interface를 추가했습니다.
- 봇 계정에 연결하지 않고 DB 계층과 핵심 동작을 검증하는 console test suite를
  추가했습니다.

### Improved (기존 기능 개선)

- 빠른 대화와 추론 중심 대화 mode를 유지하면서 이미지 생성을 포함한 AI 모델 구성과
  provider 의존성을 갱신했습니다.
- 흔한 변형 표기를 감지하고 사용자 프로필에 경고를 기록하도록 금지어 matching을
  강화했습니다.
- 활성 Cog를 하나의 `module` package로 옮기고 하나의 application entry point가
  extension을 불러오도록 개선했습니다.

### Fixed (버그 수정)

- SDK와 모델 전환 뒤 발생한 OpenAI Responses API 요청·응답 처리 오류를 수정했습니다.
- 각 명령 모듈에 중복되어 있던 DB 작업을 중앙화해 잔액과 파티 동작이 서로 달라지는 문제를
  줄였습니다.

### Breaking Changes (호환성 변경)

- 기존 prefix module과 대부분의 standalone script를 제거했습니다. 슬래시 명령만
  지원되는 interactive API가 되었습니다.
- Python import 경로가 `module.slash.*`에서 `module.*`로 바뀌었고, 지원 entry point는
  `python -m module.main`이 되었습니다.
- 모듈 애플리케이션의 문서상 최소 실행 환경이 Python 3.11 이상으로 변경되었습니다.

### Internal (내부 변경)

- 중복된 prefix, standalone, embed message script 수천 줄을 제거했습니다.
- 이후 운영 안정화의 기반이 되도록 의존성 고정과 반복 가능한 console 검증을
  정착시켰습니다.

## [0.2.0] - 2025-12-29 — 커뮤니티 유틸리티 확장

초기 유틸리티 봇은 포인트 경제, AI 도구, 금융 조회, 슬래시 명령 중심 인터페이스를 갖춘
영속형 커뮤니티 도우미로 발전했습니다.

### Added (새로운 기능)

- AI 기능 비용에 사용할 포인트 경제를 만들기 위해 일일 출석, 지갑, 랭킹, 프로필,
  럭키박스 명령을 추가했습니다.
- 포인트로 창작 요청을 할 수 있도록 채널별 빠른/고급 mode를 갖춘 Hyacine 대화와 AI
  이미지 생성을 추가했습니다.
- 주요 주식, 금리, 원자재, 암호화폐 지표를 한 번에 볼 수 있도록 `/주가`를
  추가했습니다.
- 재시작 후에도 잔액과 모집 상태가 유지되도록 출석·프로필 데이터와 파티 참가에 SQLite
  영속성을 추가했습니다.
- moderation 피드백을 커뮤니티 프로필과 연결하기 위해 사용자 프로필에 금지어 경고 횟수를
  추가했습니다.

### Improved (기존 기능 개선)

- Discord client에서 명령을 쉽게 발견할 수 있도록 활성 기능을 Cog로 재구성하고 슬래시
  명령을 주 인터페이스로 만들었습니다.
- 새 포인트 경제의 발행과 변동을 제한하기 위해 출석 보상을 조정하고 럭키박스의 일일 사용
  횟수를 제한했습니다.
- OpenAI 대화를 Responses API로 이전하고 기본 모델과 의존성 버전을 갱신했습니다.

### Fixed (버그 수정)

- OpenAI SDK 이전으로 발생한 Responses API 오류를 수정했습니다.
- 배포 프로젝트에 포함되어 있던 자격 증명과 Python cache 생성물을 제거했습니다.

### Breaking Changes (호환성 변경)

- 지원 명령 방식이 prefix 명령에서 슬래시 명령으로 이동했습니다. 이 단계에서는 기존
  prefix 파일이 참고용으로만 남았습니다.
- 전체 기능을 사용하려면 Discord, OpenAI, Google 자격 증명과 SQLite 파일을 보존할
  `DATA_DIR`가 필요하게 되었습니다.
- 출석 데이터에 `user_id`가 key인 `users` table이, 파티 데이터에 게임과 사용자가 key인
  `parties`, `participants` table이 도입되었습니다.

### Internal (내부 변경)

- 이후 기능 교체와 테스트가 가능하도록 출석, 파티, 이벤트, moderation, 금융, 대화, 이미지
  Cog로 기능을 분리했습니다.
- 명시적인 requirements 파일을 추가하고 오래된 생성물과 문서 artifact를 제거했습니다.
