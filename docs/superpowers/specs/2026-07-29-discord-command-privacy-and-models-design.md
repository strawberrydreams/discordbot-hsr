# Discord 명령 개인정보 보호 및 모델 업데이트 설계

## 목표

- `/출석`, `/지갑`, `/프로필` 성공 응답을 실행자에게만 보이게 한다.
- `/모집`의 게임 선택 메시지만 실행자에게 보이고, 선택 후 생성되는 실제 파티 모집 메시지는 공개로 유지한다.
- 여러 활성 파티 조회와 봇 재시작 후 참가 버튼 동작을 안정화한다.
- `/이벤트`는 `EVENT_CHANNEL_ID`에서만 실행되도록 보장한다.
- 대화 모델을 GPT-5.6 계열로 올리고 모델 전환 명령을 두 개의 독립 대화 명령으로 교체한다.
- Nano Banana 이미지 생성은 현재 최신 권장 모델과 API 사용 여부를 확인하고 필요한 변경만 한다.

## 명령 동작

### 개인정보 보호

- `/출석`, `/지갑`, `/프로필`: 모든 성공 응답에 `ephemeral=True`를 지정한다.
- `/모집`: 게임 선택 화면과 생성 가능한 게임이 없다는 화면에 `ephemeral=True`를 지정한다.
- 게임 선택 후 `send_party_embed`가 보내는 참가 버튼 포함 모집 메시지는 공개 응답을 유지한다.

### 채널 제한

`/이벤트`는 이미 `EVENT_CHANNEL_ID` 비교를 응답 지연 전에 수행한다. 이 구현은 유지하고 회귀 테스트로 고정한다.

### 파티 안정성

- `/파티`는 활성 파티별 embed를 모아 `embeds=`로 한 번만 최초 응답한다.
- 각 참가 버튼은 게임별 고정 `custom_id`를 사용한다.
- 게임별 View는 `timeout=None`으로 만들고 Cog 로드 시 `bot.add_view`로 등록한다.
- 이 변경 전에 생성된 메시지의 임의 `custom_id`는 복구할 수 없다. 새 코드 배포 후 생성되는 모집 메시지부터 재시작 후에도 버튼 핸들러가 복구된다.

### 대화 명령

- `/대화`, `/기본`, `/고급`을 제거한다.
- `/기본대화 내용 이미지?`: `gpt-5.6-terra`, reasoning effort `none`, 무료.
- `/고급대화 내용 이미지?`: `gpt-5.6-sol`, reasoning effort `medium`, 기존과 동일하게 2,000P 차감.
- 두 명령은 같은 채널 세션 기록을 공유하지만 모델 선택 상태는 저장하지 않는다.
- 공통 대화 처리 함수가 모델, reasoning effort, 비용을 인자로 받아 중복을 피한다.
- `/상태`는 두 명령의 모델 매핑과 직전 사용량을 표시한다.
- 대화 메시지는 기존처럼 공개로 유지한다.

### 이미지 생성

`gemini-3.1-flash-image`는 현재 Nano Banana 2의 최신 안정 모델이므로 모델 ID와 `generate_content` 응답 처리를 유지한다. 불필요한 API 전환이나 의존성 추가는 하지 않는다.

## 오류 및 포인트 처리

- 고급 대화 시작 전에 포인트를 차감한다.
- API 호출 실패 시 차감한 포인트를 기존처럼 환불한다.
- 모델 오류 상세는 콘솔에만 기록하고 Discord에는 일반 오류 메시지만 보낸다.
- 지정 채널 밖에서 `/이벤트`를 호출하면 기존 ephemeral 오류를 반환한다.

## 검증

- 변경 전에 각 개인정보 보호 응답이 `ephemeral=True`가 아닌 상태를 실패 테스트로 확인한다.
- 활성 파티가 둘 이상이어도 `/파티`가 최초 응답을 한 번만 보내는지 확인한다.
- 참가 View가 persistent 조건을 만족하고 Cog 로드 시 등록되는지 확인한다.
- 두 새 대화 명령의 등록, 모델·reasoning·비용 전달, 기존 세 명령 제거를 확인한다.
- 이벤트 채널 가드와 Nano Banana 모델 ID를 회귀 검사한다.
- 전체 `python -m test.console_tests`를 실행한다.
